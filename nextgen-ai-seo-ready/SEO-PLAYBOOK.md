## 2. Free accounts to set up once

### Google Search Console

1. Open https://search.google.com/search-console
2. Add a **Domain property**: `nextaigen.org`
3. Add the DNS TXT verification record where the domain DNS is managed.
4. Submit: `https://www.nextaigen.org/sitemap.xml`
5. Inspect and request indexing for the five URLs listed above.

Use Search Console to measure queries, impressions, clicks, CTR, indexing and Core Web Vitals. It is your source of truth for Google—not an AI rank estimate.

### Bing Webmaster Tools

1. Open https://www.bing.com/webmasters/
2. Import the verified property from Google Search Console or verify manually.
3. Submit the same sitemap.
4. Use Keyword Research, Site Scan and URL Inspection.

### Microsoft Clarity (optional)

1. Open https://clarity.microsoft.com/
2. Create a free project for `www.nextaigen.org`.
3. Add its tracking snippet only after reviewing privacy requirements.
4. Use scroll depth, heatmaps and recordings to improve calls to action—not to chase vanity traffic.

### Free testing tools

- Google PageSpeed Insights: https://pagespeed.web.dev/
- Google Rich Results Test: https://search.google.com/test/rich-results
- Schema.org Validator: https://validator.schema.org/
- Google Trends: https://trends.google.com/
- Bing Webmaster Keyword Research and Site Scan
- Chrome Lighthouse in DevTools

## 4. Safe AI content workflow

AI can help with research, structure, rewriting and gap analysis. It must not invent experience, clients, results, certifications or medical claims.

### Step A — choose a real question

Use one source:

- Search Console query with impressions
- A prospect’s real question
- A product-support question
- A workflow you have personally built or tested
- Bing Keyword Research or Google Trends

### Step B — make an evidence packet

Before prompting AI, collect:

- What you actually built
- Screenshots or interface details
- The workflow and users
- Constraints and trade-offs
- What is live versus planned
- Safety boundaries
- Any measurement you can prove

### Step C — create a brief with AI

Use this prompt:

> You are preparing a people-first SEO content brief for Next Gen AI. The audience is [AUDIENCE] searching for [QUERY]. Use only the evidence below. Do not invent clients, results, statistics, regulations, certifications or product capabilities. Identify search intent, the reader’s decisions, five useful sections, questions to answer, internal links and claims requiring verification. Evidence: [PASTE EVIDENCE].

### Step D — draft with strict boundaries

> Draft the page from the approved brief. Write in clear professional English. Lead with the operational problem, include concrete workflow details, distinguish live features from research directions, and state limitations. Avoid keyword stuffing, generic AI hype and unsupported numbers. Add a concise title, meta description, H1, suggested URL and three internal-link anchors. Mark any statement that needs verification as [CHECK].

### Step E — human review

Before publishing, answer yes to all:

- Is every factual claim true?
- Does the page add information beyond generic search summaries?
- Is project maturity stated honestly?
- Are medical or safety boundaries clear?
- Is there a named author or responsible company?
- Does the page help a buyer make a decision?
- Are there screenshots, examples, steps or trade-offs from real work?

### Step F — AI quality audit

> Audit this draft for thin sections, repetition, unsupported claims, fake certainty, keyword stuffing and generic phrases. Do not rewrite immediately. Return a table with the exact problematic sentence, risk, and a specific evidence-based correction. Also identify questions the page still fails to answer.

## 5. On-page checklist for every new page

- One descriptive, unique `<title>`
- One honest meta description
- One visible H1 that matches the page’s main topic
- Short readable URL
- Canonical URL using `https://www.nextaigen.org/`
- Useful opening paragraph—not a generic company introduction
- Logical H2/H3 hierarchy
- Links to at least two related internal pages
- At least one relevant link pointing to the new page from an existing page
- Original image or diagram with useful alt text when appropriate
- Open Graph image
- Structured data only when it matches visible content
- Updated sitemap `lastmod`
- No fake testimonials, ratings or review schema
- No `meta keywords` tag; it is unnecessary
- Request indexing after publication

## 8. Weekly 30-minute routine

1. Search Console → compare last 28 days with previous 28 days.
2. Export queries with impressions and positions 8–30.
3. Find pages with impressions but low CTR; improve title/snippet only if the page satisfies the query.
4. Check Pages/Indexing for errors.
5. Bing Webmaster Tools → review search terms and Site Scan.
6. Update one existing section using real evidence.
7. Add one useful internal link.
8. Record changes in a simple spreadsheet: date, URL, query, change, impressions, clicks, position.

Do not evaluate SEO changes after two days. Review meaningful trends over several weeks.

## 10. What not to do with AI

- Do not publish hundreds of near-duplicate location pages.
- Do not create fake case studies or performance percentages.
- Do not rewrite competitors’ pages.
- Do not add hidden keywords.
- Do not create fake FAQ, Product, Review or AggregateRating schema.
- Do not use “best AI company in Pakistan” as a claim without independent evidence.
- Do not let AI publish automatically without fact-checking.
- Do not change a page every day based on guessed rankings.

The durable strategy is straightforward: make the site crawlable, map one topic to one useful page, add evidence from real work, connect related pages, and improve using Search Console data.
